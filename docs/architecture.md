# Architecture & Ownership

Optisample turns an instrumental's recorded samples into a tracker module — Impulse Tracker (`.it`) or
FastTracker 2 (`.xm`) — under a hard byte budget. This document says which part of the package owns what, so
shared logic has one home and new code lands in the right place.

## Package map (`src/optisample/`)

| Module / subpackage | Owns | Depends on |
|---|---|---|
| `frontier.py` | The rate-distortion hull every axis a run prices is read through: the `RDPoint` protocol (`stored_bytes` + `distortion`) and `lower_convex_hull`, a Pareto filter followed by a convex-hull pop, so one rule serves the loop lengths a recording offers, the encodings a sample is swept over, and a zone's `(representative, encoding)` options alike. A leaf importing nothing in-package. | `numpy` |
| `music.py` | Pitch primitives: note names, the `pitch_label` every per-pitch artifact is filed under, `semitone_ratio`, MIDI/tuning constants. A leaf shared by everyone. | nothing in-package |
| `progress.py` | The stage-reporting boundary: the `ProgressSink` protocol every long loop reports through, a `TqdmProgress` drawing bars on stderr, the shared silent `NO_PROGRESS`, and the terminal probe deciding between them. A leaf shared by everyone. | `tqdm` |
| `parallel.py` | The fan-out boundary: `map_workers` applying a function to every item across a process pool and answering in the order given, `worker_count` turning a requested count into processes (`ALL_CORES` → one per core, capped at the items there are), and the `forkserver` start method the workers come from. Reports through `ProgressSink` as each result lands, and reads its count from the `runtime` config group. A leaf shared by everyone. | `progress` |
| `threads.py` | `bind_compute_threads`, the one compute thread per process a run is held to. Stated by `__main__` before the numerical libraries load, since each reads its count as it is imported: it holds a run to the workers it asked for, and holds a shared-out stage to the same arithmetic as one carried in-process. A leaf importing nothing. | nothing in-package |
| `seed.py` | The entropy a dither stream starts from: `DEFAULT_SEED`, the run seed every stage draws its dither from when a caller states none, and `SURROGATE_SEED`, what a proxy encode dithers from so a clip prices the same in whichever order it was reached. One home, so a run reproduces itself from one value. A leaf importing nothing. | nothing in-package |
| `model.py` | Manifest DTOs: `Manifest`, `ProjectSpec`, `InstrumentSpec`, `SourceSample`, `NoteEvent`. Samples and events carry per-CC `cc_averages`; a sample carries the padding at either end of it, `lead_in_s` before the onset and `trail_out_s` past the release, and an instrument the `pre_roll_s`/`post_roll_s` its dataset was cut with. | pydantic |
| `config/` | Pydantic **schema** for every tunable parameter; values live under `src/opticonfig/`. `OptiConfig` gathers the groups by the pipeline stage acting on them, in the order those stages run — `analysis`, `codec`, `loop`, `reduce`, `optimize`, `export`, plus the standalone `synth` and `runtime`. A group descending from `StageConfig` is a directory holding one file per member (`loop/geometry.yaml`), and every other group is one file (`runtime.yaml`); `load_config` reads whichever the annotation names. `OptiConfig.encode` gathers what the surrogate encoder needs from the two stages that settle it — the loop stage's seam and level reading beside the codec's dynamics, headroom and release ramp — so `encode` reads one bundle. | pydantic |
| `dsp/` | Signal primitives (`levels`, `envelope`, `series`, `piecewise`, `similarity`, `loopability`, `spectral`, `resample`, `quantize`, `dynamics`, `loop`, `decay`, `timebase` — audio frames, where the tracker clock itself is `trackmod.core.timing.clock`) and the surrogate codec — the `surrogate/` subpackage (`params`, `sample`, `encode`, `render`) exposing `encode`/`render`, `StoredSample`, `EncodingParams`, and the pair that puts a stored sample's ending on both sides of a comparison — `StoredSample.release_frames` (how far the ramp closing it reaches) and `closed_reference` (that ramp over the ground truth, placed by `output_frame` on the repitched output timeline). `decay` fits the `LinearDecay` a looped sample is played down by from `loop.start` on, carried on `StoredSample.decay` so the PCM stays the material and the decline the region gave up comes down outside it. `loop` owns the loop primitives every stage reads through — `loop_candidates` and `shortest_loop_frames` (what a recording offers: the rounds `loopability` reads off it, each landed on the waveform inside a window opening where the recording's own material settles and closing before its release, over a period searched around the pitch the note was played at and read between frames, an end matched to the phase the start approaches on, and a length holding at least the window a spectrum is read over so the timbre gate judges every candidate on a measurement of its own), `loop_quality` (the seam step, the level drift and the timbre distance one candidate measures), `prepare_loop` (the region readied to wrap: `level_loop` dividing it by the `LevelReading` its own material holds so it stands at the level it starts on, then `crossfade_loop` blending the seam over `seam_frames` of it, band by band, under a weighting law read off how alike each band measures across the wrap — which is what carries a struck string's inharmonic partials through the blend at the level each of them had), and `loop_at_rate` (settled bounds carried onto a stored rate) — while which candidates a recording offers belongs to `loop/`. `series` is the leaf owning the operations a series of readings is taken through — `hann_kernel` and `weighted_mean` (a unit-sum weighting and the mean under it, which holds a curve's ends where the material is), `autocorrelation` and `refined_lag` (how alike a series is to itself at each lag, and that peak read between points by the parabola through its top three), and `Readings`, the pair every fit reads a stretch through — one value per window beside the moment that window centres on, which is what puts fits taken at different window lengths on one timeline. `piecewise` fits that pair with a curve of a bounded number of corners: `fit_piecewise` places them by the walk pricing every stretch of the trajectory against the straight line through it and keeping the cheapest run of them, then solves the values they hold exactly at those positions, giving the continuous `PiecewiseCurve` / `CurveNode` a tracker's volume envelope is written from — worth a median 4.2 dB of max gap against the one straight ramp `decay` fits, on the level a recording holds past the loop it stores. `similarity` reads a recording as timbre frames and says where it settles: `window_frames` (the stretch one frame spans, whole periods of the note's own pitch so a deep note's partials resolve as clearly as a high one's), `frame_series` / `FrameSeries` (one log-mel spectrum per frame in decibels with that frame's own mean taken out, beside the level curve it was taken against — so scaling a recording moves the level and leaves the shape, and two moments compare on the sound they hold), `shape_travel` and `span_frames` (how far each frame's shape stands from the frame a given lag later, and the frames one reading is held over — the two primitives both the change rate and the loop frontier are read from), `change_rate` (that travel over `change_span_s`, per second of it, which leaves the material's movement in the reading and divides two overlapping windows' jitter out) and `settling_frame` (the frame that rate settles under `settle_db_per_s` and holds, which is where `loop` opens the window a loop is taken from). `loopability` turns that series into the rounds a recording offers: `loop_frontier` / `LoopReach` / `FrontierBounds` — every frame a round could close on priced at what the best placement ending there gives up (the step across its wrap, read over `change_span_s` of each side, plus the movement it plays in place of, read as the mean shape either side of the close), which is a cost-per-byte curve because storing a round keeps everything up to that close, and its `frontier.lower_convex_hull` is what the sweep prices. `levels` is the leaf owning amplitude/decibel conversion (`db_to_gain`, `gain_to_db`, `peak_amplitude`) and `DecayTrend` / `decay_trend`, the line a stretch's level readings make in decibels -- the domain a ringing note falls straight in, and so where the fitted decline reads the level a held note arrives at. `envelope` reads the level a recording holds frame by frame and splits it off: `power_kernel` (the unit-sum weighting a local mean square is read under, spanning two periods of the frequency it is formed at so the power ripple every tone above that carries averages away), `reading_frequency` / `level_reading` (that frequency as the recording's own pitch held inside the config's band, bundled with the floor into the one `LevelReading` every level taken of that recording is read under -- so a note two octaves up is followed as closely as the one below it, while the band caps how long the weighting runs for the deepest notes and floors it so partial beating stays in the carrier), `local_level` and `local_level_over` (that level over a whole recording or over one stretch of it, the two answering alike because the weighting has a finite reach, which is what lets a loop region be levelled at the cost of its own length), and `decompose` / `Decomposition` (`signal == level * carrier`, exact and scale-equivariant -- the level is where a recording's dynamics live and the carrier, at one loudness throughout, is where its timbre does). Levelling, the drift a report states and the fitted decay all read a region's level through it; `quantize` prices the grid and sets the stored peak (`headroom_peak`, `normalize_peak`); `dynamics` is the soft-knee compressor the sweep may buy ahead of it. | `config`, `music`, `trackmod` (`BitDepth`, the shared clock, `MAX_VOLUME`) |
| `keys.py` | `SampleKey`, the identity of a stored recording, the `DedupeGroup` projection the configured key decides, and the `nearest_key` lookup routing a played velocity to a recording. A leaf, so the loop stage and the reduction key their recordings alike without either depending on the other. | `config`, `music` |
| `loop/` | Which loop a recording is stored around, settled from the recording itself at the analysis rate: `settle` (the ladder of candidates ordered cheapest first — earliest and shortest — every rung measured, answering a `Settlement`: the frontier of `StoredLoop`s clearing every quality gate, each with the `LinearDecay` fitted from its own start, every `RejectedLoop` beside the `Gate` it fell outside — the wrap, the level or the timbre — and the span the search was bounded to; one `LevelReading` built from the recording's pitch serves the whole ladder, so every candidate is measured under the weighting the region it names is levelled by. `Settlement.settled` is the tuple `EncodingParams.loop_index` counts into, which is how a loop's length reaches the allocation as a priced axis), `stage` (`LoopRequest` / `settle_one` / `settle_loops` — one recording answers from itself and the config alone, with the pitch read off its key through `music.midi_to_freq`, which is what lets the stage share its recordings across `parallel`'s workers). | `config`, `dsp`, `keys`, `music`, `parallel`, `progress` |
| `metrics/` | Fidelity measurement (`composite`, `spectral`, `timbre`, `diagnostics`, `preprocess`) and the KiB conversions in `size`. | `config`, `dsp` primitives |
| `optimize/` | The allocation pipeline (see below). | `dsp`, `metrics`, `model`, `io`, `config`, `music` |
| `io/` | The file/format boundary: `audio` (WAV), `dataset` (`SourceDataset` — the two shapes a run reads its recordings in, and where the WAVs of either sit; `SubsetDataset`; `instrument_name`), `note_extractor` (read a NoteExtractor `.notes.json` + samples dir into the model via `load_notes`/`IngestSettings` — the manifest's own `settings.rolls` states the padding each recording was cut with, and `trail_out_s` measures from the file what is left past the note, bounded by that declared post-roll so a recording written longer than its note keeps every frame — plus a minimal `dump_notes` writer, declaring no rolls, for the demo and the reduced datasets), `sample_dir` (read a directory of recordings as the grid its filenames spell — key, dynamic and controller averages off the name, each take standing for one note held for as long as it sounds between the padding the ingest flags state — and slice one into a directory of the same kind), `source` (`load_source`/`write_source_subset` — the one seam that answers for either shape, so every stage past the ingest reads one), `subset` (carve the share of a dataset that spans its pitch and velocity ranges into a dataset of the same shape, each kept note written exactly as its source states it), the `tracker/` subpackage (`target` — the `trackmod` seam: `ExportTarget` answers what a record costs, how tall a pattern may be, which keys the keyboard numbers, how a note is released, whether the format keeps a per-sample gain, binds a song to a module of the configured format, and binds one instrument and its own samples to the standalone file that format writes), `module_read` (round-trip through the independent `xmodits` ripper), `render` (openmpt123 wrapper). | `config`, `music`, `trackmod` |

### Inside `optimize/`

- `operating_points.py` — per-sample rate-distortion sweep + lower convex hull (`SourceClip`, `OperatingPoint`).
- `tasks.py` — pitch-task construction (from one `TaskInputs` bundle: the survivors, the velocity map, the reduction rules, the analysis rate and the cost exponent) and the **single** reconstruction scorer (the objective), plus the accessors every consumer of a scored note shares: `Event.scored_span` (the stretch of recording a class is measured over), `Event.scored_reference` (that stretch closed by the ramp the stored sample it is compared to closes on, so the ramp stands on both sides and the score reads the codec) and `render_event` (the audio a stored sample produces for it), so a fidelity score and any WAV written beside it describe the same pair. `Event.objective_weight` is the one multiplier the objective weighs a class by — its playing time times its `energy_weight` — held apart from `weight`, which stays the seconds the reports state.
- `velocity_map.py` — the loudness-matched velocity→volume map.
- `knapsack.py` — the MCKP byte-budget DP (exact + Lagrangian).
- `weighting.py` — `energy_weight`: what a note's own level makes its distortion worth. The composite scores loudness-matched signals, so its fidelity is a relative error; this raises the scored span's mean energy to `optimize.energy_exponent` and full scale weighs 1.0, which is what turns that relative error into the error heard in the mix.
- `reduce/` — everything that shrinks the problem before allocation begins, as a subpackage: `dedupe` (one survivor per identity — the shortest recording that covers its key's material, chosen from the WAV headers alone), `events` (the notes at a pitch collapsed into the classes that reconstruct alike, over a geometric duration grid), `bandwidth` (`StoredFormat` — the rate, depth and compression one sample is kept at, settled from the clip's own band: `clip_band_hz` measures where its spectrum falls away, `useful_rate_hz` reads the rate that carries it at the transpose a demand plays it at, and `stored_format` takes the lowest rung of the ladder reaching that, with `stored_encodings` offering that one format once per loop the stage found plus once for the trimmed span they stand against, so how much of a note is stored reaches the hull as an axis of its own), `grids` (`GridContext` — the validated config narrowing runs off, small enough to hand a worker process — plus `narrow_grid` for one pitch and `narrow_grids` sharing the pitches across `parallel`'s workers), `trim` (what a recording contributes: the span up to where its decay falls under `tail_floor`, bounded by `max_length_s`, plus the `silence_floor` screen that keeps a take that never sounded out of the dataset and the material narrowing that follows it), `summary` (the stage's own outcome — `ReductionSummary`: each axis stated as before → after, the format every played pitch is stored at with the encodings swept over it, and each kept recording measured against the material its pitch asks of it).
- `layers/` — velocity layering as a subpackage: `bands` (`Band`, a run of one axis with both ends inside it, and `VelocityBand` naming its own; `VelocityCells`, the elementary velocity ranges cut from the material's own playing time; and `VelocityLayers`, one split of the axis into the bands an instrument stores, answering `band_index` for the instrument a note's dynamic is played through), `tasks` (`band_tasks` / `layered_tasks` — one task list per band, built by restricting the material to the notes the band covers, so each band keeps the recording nearest its own loudest dynamic), `allocate` (`allocate_layers` — prices every split the cap allows, solves the pitch partition for each, and keeps the one that earns its extra instruments by `min_gain`), `slots` (`InstrumentSlot` / `SlotLayout` / `pack_slots` — a band's stored samples cut into the instruments the format has room to write them in, each owning an ascending run of keys and naming the file it is written to through `file_label`, with `key_band` giving the stretch of keyboard each one owns among its band's — the tiling both `instrument` and the bank manifest route by — plus `reserved_slots`, the worst case the byte budget is taken against; the one projection the exporter, the report, `plan.json` and the instrument files all state a plan's written instruments from).
- `grouping/` — pitch-zone grouping as a subpackage: `cost_model` (zone-option enumeration over a sequence of `ZoneSegment`s, one per velocity band, bounded by the span cap on how wide a zone may be and sharing one priced `ProxyGrid` per `(representative, stored length)`), `stores` (the scoring stage: every zone's ask pooled into one `StoreRequest` per representative, so each encode and each reconstruction lands in exactly one worker at any worker count), `solve` (exact partition + allocation DP over the segments laid end to end, each recovered zone stamped with the segment it came from, which is the layer it answers for, and charging every stored sample a caller-set `reserve` beyond its own bytes), `reserve` (`solve_within_cap` — the sample cap as a Lagrangian relaxation: it walks once for free, and where the cap bites it charges each stored sample the price that draws the walk into fewer, wider zones and narrows toward the smallest such charge), and the `__init__` orchestration + `GroupedInstrumentPlan`.
- `orchestrate/` — the ungrouped end-to-end pipeline as a subpackage: `cost_model` (per-pitch rate-distortion sweep over the encodings the reduction settled → knapsack items), `solve` (MCKP allocation + per-pitch plans), `settings` (`OptimizeSettings`, holding the metrics config its `composite` is assembled from, so the whole bundle is validated values a worker process can be handed), `audio` (`load_instrument_audio` — decodes the survivors `reduce/dedupe` picks into one signal per `SampleKey`, cutting each `lead_in_s` and `trail_out_s` away so the signal runs from the onset to the release, applying `reduce/trim`, and answering a `LoadedInstrument`: the recordings that carried signal, the material they can serve, and the `RecordingScreen` saying what that left out), `looping` (`run_loops` — the loop stage over a loaded run, bounding each recording's search by the longest note its pitch plays and answering a `LoopedInstrument`: the whole `Settlement` per recording for a report to read, and the `StoredRecordings` bundle — audio, the loops each recording offers, and the one rate they share — every stage after it encodes from), `staging` (`instrument_peak` and `staged_encode` — the one amplitude an instrument's clips are normalized against, fixed before anything is swept for the formats that carry their balance in the PCM), and the `__init__` orchestration (`prepare_run` → `RunInputs`, which runs the bandwidth pre-pass once, and `allocate_instrument`, which sweeps and solves from it) that pitch-zone grouping reuses through `allocate_instrument_grouped`. A run prepares once and allocates per strategy, so both read back the same tasks, context and `ReductionSummary`.
- `export/` — the plan → module bridge as a subpackage: `context` (`ExportContext`), `samples` (plan units → stored samples numbered across the whole plan, plus one keymap per written instrument routing that slot's own keys onto them, each sample carrying the `sample_gains` step that puts the loudest recording at the format's top gain and the rest under it by the margin they were recorded by), `coverage` (`covered_routing`, widening a routing to answer every key the format numbers from the recording nearest each one, and `key_coverage`, the reading the report and `plan.json` state it by), `material` (note events → pattern grids + the order list, each cell naming the instrument and the volume the `Voicing` reads off the note's dynamic and pitch), `envelope` (the volume curve an instrument plays its voices down by: `shared_decay` picks the one shape a slot's samples share, `volume_envelope` states it as breakpoints in seconds and hands them to `trackmod.core.envelopes.curve.timed_envelope` for the tick grid, and `decay_dispersion` states what sharing it costs the sample it suits worst), and the `__init__` orchestration (`build_song`, writing one `Instrument` per slot, and `build_module`).
- `dp.py` — the feasibility guard shared by both byte-indexed allocation DPs (`AllocationInfeasibleError`, its `BudgetInfeasibleError` case and `require_feasible`), so the knapsack and grouping solvers reject an allocation out of reach with one family of error and the artifact dump records any of them as the reason a strategy wrote no plan.
- `plans/` — plan value objects, grouped as a subpackage rather than one bag-of-classes module: `strategy` (the `StrategyPlan` protocol + normalized `SampleUnit` that export/artifacts read so they never branch on the plan type), `budget`, `ungrouped`, `grouped`.
- `report.py` — human-readable text reports for both strategies, each opening with the reduction block the pre-optimization stage's summary fills in; the grouped report then states the instruments the plan is written as before the zones it allocated within them.

## Rules

1. **Shared primitives have one home.** Every tracker-format fact — record layouts and what they cost, the
   note numbering, the per-format limits, the shared clock, the note-volume ceiling — lives in
   [`trackmod`](../trackmod) and reaches the pipeline through `io/tracker/target.py`. Pitch/music math lives in
   `music.py`, the KiB conversions in `metrics/size.py`, and the byte-budget policy in
   `optimize/plans/budget.py`. Import from the owner — do not re-derive.
2. **Config is schema, not values.** No tunable value defaults live in Python; the YAML tree under
   `src/opticonfig/` is the single source, laid out one directory per pipeline stage. Config loads once at the
   entry point and threads down as explicit arguments.
3. **One responsibility per module.** Keep data shapes, algorithms, and reporting/serialization separated. When
   a group of related types would otherwise become a bag of classes, make it a small subpackage.
4. **No pass-through re-exports.** `__init__` exposes only its own subtree's public API; do not add re-export
   shims so other modules can import through them. Import shared helpers directly from their owner.
5. **Behaviour is frozen unless a change is requested.** Refactors keep the optimizer output bit-identical; the
   demo end-to-end numbers are the regression contract (see `docs/guidelines.md` and the plan's verification).
6. **External tools sit behind a typed, probed boundary.** `openmpt123` is wrapped in `io/render.py` with a
   runtime `openmpt123_available()` probe; `tqdm` in `progress.py` behind `ProgressSink` with a
   `bars_are_watchable()` terminal probe. Callers degrade gracefully instead of branching on the environment.
7. **One place branches on the format.** `ExportTarget` is where `TrackerFormat.IT` and `TrackerFormat.XM`
   part ways; everywhere else asks the target and stays format-agnostic. Adding a format means adding its
   arms there and its settings to `config/tracker.py`.
